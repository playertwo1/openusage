# Windows Presentation Direction

Mode: Operate. Build path: code-led, adapting the user's explicitly pinned Mac reference rather
than inventing a new identity. No generated comp or decorative raster assets are required.

## First Viewport

A 440-logical-pixel tray panel: original OpenUsage mark, restrained refresh/hide controls, a compact
Overview/Accounts/Settings switch, then grouped provider cards. Each provider uses its original mark;
each account has its saved name/plan. Usage rows have a label, slender blue meter, value and reset.
The footer contains refresh state and Add Account. There is no fabricated spend overview.

## Interaction

Click a value to switch used/remaining globally; click a reset to switch countdown/date. Quick
filters select all/favorites. Settings offer system/light/dark, density, cards/list, text size,
privacy, startup and alerts. Account and metric menus preserve reordering/removal/visibility.
Do not add tooltips. Keyboard focus must be visible and every icon button must be named.

## System And Quality Bar

Use the current Mac's restrained typography, 12px grouped corners, off-white/graphite surfaces and
blue/orange/red severity language. Native WPF gives crisp text and real controls; preserve existing
OAuth/network/storage behavior. Both theme variants, compact list, management, settings, empty,
error/long account names, add-account and sign-in must render without overlap at 400–500 logical
pixels. Enlarged text scales once and stays scrollable. All values come from provider fixtures in
review captures; real accounts are never included in shared evidence.

## Verification

`UiChecks` renders the actual WPF views at 144 DPI and exercises settings persistence, used/remaining,
favorites, navigation, visibility, privacy, text scaling, setup and cancellation. Existing protected
account files must load without losing credentials. Native Windows code is outside the web-only
Impeccable detector's scope; finish review must use the supplied captures and native conventions.
